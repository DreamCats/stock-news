# 源头雷达 · 榜单指标解读

> 面向阅读者（业务 / 老板），解释 `sn source scan` 榜单每一列的含义、算法口径和怎么看。
> 实现见 `src/stock_news/source/scanner.py` 与 `features.py`，本文随算法更新。

## 0. 一句话定位

源头雷达回答一个问题：**「哪个新词，平时没人提，今天突然全网刷屏，而且别人开始自发接棒？」**

这种「**低频拐点**」最值钱——平时是冷词（基线低）、今天突然放量（倍率高）、且是真跨群扩散（不是一个人刷屏），往往是新题材从概念走向落地的最早信号。

## 1. 榜单长什么样

```text
# | 词           | 信号     | 倍率  | 基线/天 | 当日放量   | T+5接力  | 落地个股   | 裁决
1 | 原生多模态 ✓真 | 低频拐点 | 40.0× | 0.47   | 20次/19群 | 9人/15群 | —        | 已验证扩散（9 人/15 群接力）
2 | AI工厂 ✓真     | 低频拐点 | 26.0× | 0.5    | 13次/13群 | 7人/9群  | 工业富联  | 已落地个股（1 只）
```

## 2. 每列含义与算法口径

| 列 | 含义 | 怎么算 | 解读 |
|----|------|--------|------|
| **词** | 候选源头概念词 | 从消息原文按规则切词（`#话题`、`【标题】`、`X新概念/新方向`、`A+B` 组合等） | `✓真` 表示已被 T+N 事后回看验证为真信号 |
| **信号** | 信号分层 | 见 §3 | `低频拐点` 优先级最高 |
| **倍率** | 放量突变强度（**核心指标**） | `当日提及次数 ÷ max(基线/天, 0.5)` | 越高越说明「平时冷、今天炸」 |
| **基线/天** | 这个词平时有多冷 | 首现日**往前 30 天**（lookback）总提及 ÷ 30 | `0.47` = 过去一个月平均每天才被提 0.47 次，是冷词 |
| **当日放量** | 首现当天炸了多少 | `当天提及总次数 / 覆盖的不同群数` | `20次/19群` = 当天 20 条消息散落在 19 个群 |
| **T+N 接力** | 别人有没有自发接棒 | 首现**之后**窗口内，**排除首发人**的独立人数 / 覆盖群数 | `9人/15群` = 9 个**别人**接了棒 |
| **落地个股** | 接力消息里抽出的个股 | 窗口内接力消息中 `target_type=stock` 的标的名 | 链路终点是个股埋伏，最硬的命中 |
| **裁决** | 一句话定性 | 见 §4 | 站老板视角的结论 |

### 倍率为什么是核心

打分函数 `score_candidate` 的主权重就是：

```
score += min(倍率, 20) × 1.5      # 放量突变是主权重
score += min(当日跨群数, 8) × 1.5  # 真扩散而非单点刷屏
# 基线分层：基线 ≤ 2/天 直接 +8 分（低频起量最香），基线 > 10/天 反而扣分
```

逻辑：平时没人提 + 今天突然刷屏 + 真跨群 = 最高分。高频旧主题（天天有人提）会被**降权但不剔除**。

## 3. 信号分层（`signal_type`）

按优先级从高到低：

| 信号 | 触发条件 | 含义 |
|------|----------|------|
| **低频拐点** | 基线 ≤ 2/天 **且** 倍率 ≥ 3 **且** 当日 ≥ 3 群 | 冷词突然跨群放量，最值钱 |
| **放量加速** | 基线 2~10/天 + 倍率 ≥ 2 + 当日 ≥ 3 群 | 中频题材的二次催化 |
| **扩散带股** | 有个股 + 后续提及 ≥ 3 | 已经带出个股的线索 |
| **全新首现** | 历史从未出现过 | 全新词，但还没验证扩散 |
| **普通线索** | 其它 | 兜底 |
| **高频旧主题** | 基线 > 10/天 | 天天刷的老词，降权 |

## 4. 裁决规则（`t3_verdict`，站老板视角）

判断标准是「**别人自发接力才算真起势**」——单人在多群刷屏不算数：

| 裁决 | 条件 | 是否标 `✓真` |
|------|------|------------|
| **已落地个股（N 只）** | 接力消息里抽出了个股 | ✓ 最硬命中 |
| **已验证扩散（X 人/Y 群）** | ≥ 2 个独立接力人 **且** ≥ 3 个群 | ✓ |
| **弱扩散（仅 X 人/Y 群）** | 只有 1 个人接 | ✗ |
| **单点哑火（无人接力）** | 首发后没人提 | ✗ |

> 关键设计：接力人数**排除首发人本人**，防止「一个人在 10 个群刷同一句话」被误判成扩散。

## 5. 常见疑问

### Q：今天才 6.1，为什么 T+5 / T+3 接力已经有值？

不是 bug，是口径问题。接力统计的窗口是 `首现时间点 < ts ≤ 首现 + N天`：

```python
deadline = first_time + timedelta(days=horizon_days)
if not (first_time < ts <= deadline):   # 首现"之后" ~ 截止日
    continue
```

接力从**「首现那条消息的时间点之后」**就开始算——**当天稍晚的提及就已经计入接力**，不需要真的等满 N 天。T+N 只是个**上限边界**：数据够不到 N 天，就用目前已落库的数据统计到哪算哪。

所以「原生多模态」9 人/15 群，绝大部分是 **6.1 当天首现之后、同一天晚些时候**别人陆续提的（加上已抓到的次日零星数据）。

> 含义：榜单跑得越早（离首现越近），接力数偏小是正常的；隔几天再回看同一天的榜单，接力数会继续长。

### Q：「当日放量 19 群」和「T+N 接力 15 群」为什么不一样？

- **当日放量 19 群** = 首现**当天**全部提及覆盖的群（**含**首发人自己在多个群发的）
- **T+N 接力 15 群 / 9 人** = 首现**之后**窗口内的群；`9人` 特意**排除了首发人**

两个数统计的时间段和口径都不同，不一致是正常的。

### Q：「基线/天」是小数正常吗？

正常。它是「过去 30 天总提及 ÷ 30」的日均值，冷词自然是 `0.47`、`0.5` 这种小数。倍率分母对基线做了 `max(基线, 0.5)` 下限保护，避免除以 0 或被极小基线放大到失真。

## 6. 怎么用这张榜

1. **先看「裁决」列**：`✓真 / 已落地个股` 的优先级最高，是已被事后数据验证的信号。
2. **再看「倍率 + 基线」**：基线低（< 1）+ 倍率高（> 10）= 典型低频拐点，新题材的最早信号。
3. **「落地个股」是终点**：链路设计上，源头词最终要落到个股埋伏，有个股的线索可重点跟。
4. **接力数会随时间增长**：当天跑的榜单接力偏小是正常的，关键看趋势。
