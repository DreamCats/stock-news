# 呈现方式与部署形态

## 1. 老板友好的主链路

老板平时不一定在电脑前，所以核心入口不应该是 PC BI 或 PDF，而应该是：

```text
收到 channel 推送 -> 看 30 秒 AI 简报 -> 点进手机 H5 看重点票/重点人 -> 必要时追溯原文
```

## 2. 推荐呈现方式

### 2.1 每日 AI 简报

形式：推送到 channel。

作用：主动给老板推结论，不要求老板打开系统。

内容示例：

```text
【今日推荐简报】
重点观察：3 只
高胜率推荐人动态：5 条
多人共振：2 只
风险提示：1 条

按钮：
[今日推荐池] [推荐人排行榜] [查看原文]
```

### 2.2 今日推荐池

形式：手机优先 H5/轻网页。

不建议做成大表格，手机看表格体验差。建议做成卡片流：

```text
XX股份
信号等级：高
推荐人：A / B
共振来源：个人消息 1 条，群消息 2 条
推荐人历史：5日胜率 68%，平均收益 +4.2%
AI 摘要：PCB 扩产逻辑，短线热度高
状态：重点观察

[看原文] [加入观察] [忽略]
```

### 2.3 推荐人排行榜

形式：手机优先 H5/轻网页。

内容示例：

```text
A 推荐人
样本数：42
5日胜率：68%
平均收益：+3.7%
最大回撤：-5.2%
擅长：PCB / 半导体 / 汽车
风格：短线强，追高风险中等

[看最近推荐] [看历史表现]
```

### 2.4 周报/月报 PDF

形式：定时生成 PDF 并推送到 channel。

定位：复盘和汇报，不作为日常决策主入口。

适合内容：

1. 本周高胜率推荐人。
2. 本周推荐表现复盘。
3. 本周多人共振标的。
4. 亏损案例复盘。
5. 推荐人画像变化。

## 3. 是否需要云服务器

### V0：本地验证，不强依赖云服务器

目标是验证数据和模型是否有价值。

形态：

```text
脚本拉 API -> 本地 JSON/SQLite -> 生成 Markdown/HTML 简报
```

### V1：云端定时任务 + channel 简报

需要一台云服务器或等价的定时任务环境。

形态：

```text
定时任务
-> 拉微信 API
-> 清洗/分类/结构化
-> 存数据库
-> 生成每日 AI 简报
-> 推送 channel
```

### V2：手机 H5 推荐池/排行榜

需要云服务器。

原因：

1. 手机需要打开一个 URL。
2. 页面需要实时读取推荐数据。
3. 需要筛选、排序、原文追溯。
4. 最好有登录或访问控制。

最小架构：

```text
云服务器 + Web 服务 + 数据库 + H5 页面
```

H5 页面可以包括：

```text
/recommendations  今日推荐池
/senders          推荐人排行榜
/stocks           个股共振页
/messages         原文追溯
```

### V3：周/月 PDF 自动复盘

不一定必须云服务器，但最好和 V1/V2 共用同一套服务端。

形态：

```text
云服务器定时生成 PDF -> 自动推送到 channel
```

## 4. 推荐落地节奏

```text
V0 本地验证
V1 云端定时任务 + channel 简报
V2 手机 H5 推荐池/排行榜
V3 周/月 PDF 自动复盘
```

第一阶段不要先投入复杂前端。先本地验证数据分类、推荐抽取、推荐人评价是否有效；模型跑通后，再上云做推送和 H5。
