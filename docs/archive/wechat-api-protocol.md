# 微信消息 API 协议说明

## 1. 接口概览

当前有两个微信消息接口：

| 接口 | 用途 |
| --- | --- |
| 个人消息 | 拉取个人微信消息 |
| 个人群 | 拉取微信群消息 |

两个接口的请求方式一致，区别是 `name` 参数不同。

## 2. 请求协议

### 请求方式

```text
GET
```

### 请求地址

```text
https://example.com/api
```

### Query 参数

| 参数 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| name | string | 是 | 个人消息 / 个人群 | 数据源名称 |
| starttime | string | 是 | 20260521220000 | 开始时间，格式为 `yyyyMMddHHmmss` |
| endtime | string | 是 | 20990101000000 | 结束时间，格式为 `yyyyMMddHHmmss` |

### 请求示例

个人消息：

```text
https://example.com/api?name=个人消息&starttime=20260521220000&endtime=20990101000000
```

个人群：

```text
https://example.com/api?name=个人群&starttime=20260521220000&endtime=20990101000000
```

## 3. 返回协议

### 统一返回格式

接口返回 JSON 数组：

```json
[
  {
    "内容": "消息正文",
    "发送人": "发送人名称",
    "时间": "2026-05-21 22:59:52"
  }
]
```

### 个人消息字段

| 字段 | 类型 | 是否总是出现 | 说明 |
| --- | --- | --- | --- |
| 内容 | string | 是 | 原始消息正文 |
| 发送人 | string | 是 | 消息发送人 |
| 时间 | string | 是 | 消息发送时间，格式为 `yyyy-MM-dd HH:mm:ss` |

实测结果：

| 指标 | 值 |
| --- | --- |
| HTTP 状态 | 200 |
| Content-Type | application/json |
| 顶层类型 | list |
| 样本记录数 | 29 |
| 时间范围 | 2026-05-21 22:00:20 -> 2026-05-21 22:59:52 |

### 个人群字段

| 字段 | 类型 | 是否总是出现 | 说明 |
| --- | --- | --- | --- |
| 内容 | string | 是 | 原始消息正文 |
| 发送人 | string | 是 | 消息发送人 |
| 时间 | string | 是 | 消息发送时间，格式为 `yyyy-MM-dd HH:mm:ss` |
| 群名称 | string | 是 | 消息所在微信群名称 |

实测结果：

| 指标 | 值 |
| --- | --- |
| HTTP 状态 | 200 |
| Content-Type | application/json |
| 顶层类型 | list |
| 样本记录数 | 158 |
| 时间范围 | 2026-05-21 22:01:30 -> 2026-05-21 22:59:57 |

## 4. 字段映射建议

后续进入系统内部后，建议把中文字段转换为统一英文结构：

| API 字段 | 内部字段 | 说明 |
| --- | --- | --- |
| 内容 | raw_content | 原始消息正文 |
| 发送人 | sender | 发送人/推荐人 |
| 时间 | message_time | 消息时间 |
| 群名称 | group_name | 群名称，仅群消息有 |
| name 参数 | source | 数据源，如个人消息、个人群 |

内部标准消息结构：

```json
{
  "source": "个人群",
  "group_name": "某微信群",
  "sender": "某推荐人",
  "message_time": "2026-05-21 22:59:57",
  "raw_content": "【国金计算机&电子】再谈PCB的半导体化"
}
```

## 5. 需要进一步确认

1. 是否存在未公开的分页参数，当前已测试的常见分页参数未生效。
2. 是否有限流或访问频率限制。
3. 是否有鉴权，当前接口样例未体现 token、cookie 或签名。
4. `name` 是否只有 `个人消息`、`个人群` 两种，还是还有其他数据源。
5. 时间参数是否包含边界值，即是否包含 `starttime` 和 `endtime` 当秒的数据。
6. 返回记录的排序规则，当前样本看起来接近按时间倒序，但需要确认。
7. 是否可能返回空数组、错误对象或非 200 状态。

## 6. 分页参数测试

使用固定历史窗口 `20260521220000` 到 `20260521223000` 测试，避免实时新增消息影响判断。

测试过的参数：

| 参数组合 | 个人消息 | 个人群 | 结论 |
| --- | --- | --- | --- |
| 不加分页参数 | 19 条 | 62 条 | 基准 |
| page=1&pageSize=10 | 19 条 | 62 条 | 未生效 |
| page=2&pageSize=10 | 19 条 | 62 条 | 未生效 |
| page=1&pagesize=10 | 19 条 | 62 条 | 未生效 |
| pageNum=1&pageSize=10 | 19 条 | 62 条 | 未生效 |
| pageNum=2&pageSize=10 | 19 条 | 62 条 | 未生效 |
| offset=0&limit=10 | 19 条 | 62 条 | 未生效 |
| offset=10&limit=10 | 19 条 | 62 条 | 未生效 |
| limit=10 | 19 条 | 62 条 | 未生效 |

当前结论：接口很可能不支持这些常见分页参数，或分页参数名称不是以上形式。现阶段建议用时间窗口做增量拉取，例如按 5 分钟、10 分钟或 1 小时切片。
