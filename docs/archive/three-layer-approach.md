# 微信投资推荐系统三层思路

## 0. 问题定义

老板真正要解决的不是“有没有数据”，而是每天接收到大量投研和推荐信息，但这些信息太散、太吵、不可验证，最后很难变成可执行的投资判断。

更准确地说，项目要把老板每天依赖的信息流和判断过程数字化、结构化、可复盘。

所以项目要解决的是一条闭环：

```text
投研消息 -> 信息归类 -> 观点链沉淀 -> 推荐人/主题评价 -> 决策辅助与复盘
```

核心目标是识别推荐人的规律和 alpha：谁历史胜率高，谁适合短线，谁擅长某些板块，谁的推荐虽然胜率高但回撤大。

## 1. 底层数据

这一层先解决“数据到底有什么、质量怎么样、能不能持续拿到”的问题。

当前微信 API 初步观察：

| 来源 | 记录数 | 字段 |
| --- | ---: | --- |
| 个人消息 | 29 | 内容、发送人、时间 |
| 个人群 | 158 | 内容、发送人、时间、群名称 |

接口返回是标准 JSON 数组，每条记录是一条消息。当前字段足够支撑第一版数据清洗和推荐抽取。

底层数据需要继续确认：

1. 微信 API 的时间范围、分页、限流和稳定性。
2. `发送人` 是否能稳定标识同一个推荐人。
3. 群消息里的 `群名称` 是否能作为来源维度。
4. 冈底斯、阿尔法派的数据获取方式和字段格式。
5. 后续行情数据源，用于计算推荐后的收益和胜率。

可以先用脚本检查接口格式：

```bash
python3 scripts/inspect_wechat_api.py --sample-size 2 --content-width 120
```

## 2. 模型设计

这一层解决“怎么把聊天内容变成可比较、可回测、可建模的数据”。

核心模型可以拆成三类：

| 模型 | 作用 |
| --- | --- |
| 消息解析模型 | 从原文里识别股票、行业、动作、推荐理由、时间周期 |
| 推荐标准化模型 | 把不同来源内容统一成标准推荐格式 |
| 观点链模型 | 识别同一推荐人围绕同一主题/标的的前后变化 |
| 推荐人评价模型 | 统计每个推荐人的胜率、收益、回撤、擅长板块和适合周期 |

推荐标准化结果建议包含：

| 字段 | 说明 |
| --- | --- |
| source | 来源，如个人消息、微信群、冈底斯、阿尔法派 |
| group_name | 群名称，个人消息可为空 |
| sender | 推荐人 |
| message_time | 消息时间 |
| raw_content | 原始内容 |
| stock_name | 股票名称 |
| stock_code | 股票代码 |
| action | 买入、卖出、关注、加仓、减仓、观望 |
| horizon | 日内、短线、波段、中线 |
| confidence | 推荐强度 |
| reason | 推荐理由 |
| sector | 行业/题材 |
| opinion_id | 同一观点链 ID |
| update_type | 首次提出、强化、补充、修正、反转、撤回 |

评价模型不要只看胜率，还要看：

1. 推荐次数，避免样本太少。
2. 推荐后 1日、3日、5日、10日、20日收益。
3. 最大回撤。
4. 平均收益和盈亏比。
5. 擅长行业、题材和市场环境。

## 3. 应用层

这一层解决“这些数据最终怎么辅助投资判断”。

第一版不建议直接做自动交易，先做决策辅助：

| 应用 | 价值 |
| --- | --- |
| 每日推荐池 | 汇总当天被识别出的股票推荐 |
| 推荐人榜单 | 看谁历史表现更稳定 |
| 个股共振页 | 看同一只股票是否被多人、多群、多来源推荐 |
| 原文追溯 | 每条结构化推荐都能回到聊天原文 |
| 回测面板 | 对比推荐后的真实行情表现 |

推进顺序建议：

1. 先把微信 API 数据拉通，确认格式和稳定性。
2. 做消息解析和标准化推荐表。
3. 接行情数据做回测。
4. 做推荐人画像和榜单。
5. 最后再讨论交易信号、仓位和风控。

给老板沟通时可以这样表达：

> 我想先按三层来推进：第一层先看清楚底层数据源，包括微信 API、冈底斯、阿尔法派分别能拿到什么字段、数据是否稳定；第二层再设计模型，把聊天里的非结构化内容归纳成标准推荐格式，并统计不同推荐人的胜率、收益和擅长方向；第三层再解决应用层，比如每日推荐池、推荐人榜单、个股共振和回测面板。这样不会一上来就做界面或交易，而是先验证数据和模型是否真的能支撑投资决策。
