# 交付宏图

## 核心定位

这个项目不是一上来交付一个“炒股系统”，而是把老板每天依赖的信息流和判断过程数字化、结构化、可复盘，逐步沉淀成“推荐人 alpha 数据系统”。

最终闭环：

```text
投研消息 -> 信息归类 -> 观点链沉淀 -> 推荐人/主题评价 -> 决策辅助与复盘
```

## 1. 数据资产化

先交付一个能持续运转的数据底座：

```text
微信 / 冈底斯 / 阿尔法派 / 其他源
-> 原始消息库
-> 清洗后的消息库
-> 标准化推荐库
```

这一层的价值是：老板以后不再靠翻聊天记录，而是所有投研消息都有记录、有分类、有原文、有来源、有时间。

交付物：

1. 数据源接入。
2. API 协议文档。
3. 原始消息表。
4. 消息分类表。
5. 标准化推荐表。
6. 数据质量报告。

## 2. 推荐人 alpha 与观点链模型

这一层是项目真正的核心：

```text
谁说了什么
-> 推荐了什么
-> 前后观点如何变化
-> 推荐后表现如何
-> 这个人有什么规律
```

不只统计“胜率”，而是建立推荐人画像和观点链。

核心指标：

1. 推荐次数。
2. 推荐胜率。
3. 推荐后 1日、3日、5日、10日、20日收益。
4. 最大回撤。
5. 盈亏比。
6. 擅长板块。
7. 擅长周期。
8. 是否经常追高。
9. 是否适合开盘跟、收盘跟、观察后跟。
10. 是否只在特定行情里有效。
11. 同一主题是持续强化、补充证据、提示风险，还是观点反转。

沉淀结果：

1. 推荐人排行榜。
2. 推荐人画像。
3. 推荐人可信度评分。
4. 个股/板块共振信号。
5. 观点演变记录。

## 3. 交易辅助应用

最后交付老板每天能用的操作台：

1. 今日推荐池。
2. 高胜率推荐人动态。
3. 多人共振个股。
4. 重点观察池。
5. 回测面板。
6. 风险提示。
7. 原文追溯。

老板每天打开后，不再看到一堆聊天，而是能快速回答：

1. 今天谁推荐了什么？
2. 这个人历史准不准？
3. 这只票有没有多人共振？
4. 推荐后通常第几天表现最好？
5. 当前是直接关注、观察，还是过滤？
6. 这条信号的原文是什么？

## 4. 版本节奏

### V0：数据看清楚

目标：接 API、看格式、分类消息、确认哪些是真推荐。

交付：

1. 微信 API 探查脚本。
2. API 协议文档。
3. 半小时/一天样本分析。
4. 消息类型分类标准。

### V1：推荐结构化

目标：把聊天消息变成标准推荐表，能按人、股票、来源查。

交付：

1. 标准化推荐 schema。
2. 消息分类模型。
3. 股票/板块/动作/周期抽取。
4. 原文追溯能力。

### V2：回测和排名

目标：接行情，算推荐后表现，做推荐人胜率榜和画像。

交付：

1. 行情数据接入。
2. 推荐后多周期收益计算。
3. 推荐人胜率榜。
4. 推荐人画像。
5. 个股/板块共振统计。

### V3：交易辅助台

目标：把结果变成老板每天能使用的交易辅助界面。

交付：

1. 今日推荐池。
2. 高胜率推荐人动态。
3. 重点观察池。
4. 风险提示。
5. 回测面板。
6. 原文追溯。

## 5. 对外表达

可以这样和老板描述：

> 我们不先承诺直接自动交易，而是先构建一套能验证谁靠谱、哪些信号值得跟的系统。第一步把数据源和消息格式吃透，第二步把聊天内容标准化成推荐数据，第三步接行情回测出推荐人胜率和规律，最后再做每日推荐池、共振信号和交易辅助台。
