# 投资推荐数据归纳与交易辅助系统方案草稿

## 1. 背景与目标

当前老板的核心诉求是：把微信个人消息、微信群消息，以及冈底斯、阿尔法派等短信/段子推荐源统一整理成可分析的投资推荐数据，进一步识别不同推荐人的规律、胜率和适用场景，最终辅助交易决策。

背后的真实痛点是：投研和推荐信息太散、太吵、不可验证。老板不是缺信息，而是缺少一套机制，把分散的消息变成可归类、可回测、可排名、可辅助交易的推荐信号。

本阶段目标不是直接自动交易，而是先完成三件事：

1. 把非结构化聊天内容归纳为标准化推荐记录。
2. 建立推荐人维度的统计、胜率和风格画像。
3. 做出可视化看板和回测框架，支持人工判断是否跟单。

## 2. 已知数据源

个人消息：

```text
https://example.com/api?name=个人消息&starttime=20260521220000&endtime=20990101000000
```

个人群：


接口初步观察到的字段：

| 字段 | 含义 |
| --- | --- |
| 内容 | 原始聊天文本 |
| 发送人 | 推荐人或消息发送者 |
| 时间 | 消息发送时间 |

### 补充数据源

| 数据源 | 用途 |
| --- | --- |
| 冈底斯 | 投资观点、个股推荐、板块方向 |

| 行情数据 | 用于计算推荐后的涨跌幅、最大回撤、胜率 |
| 股票基础信息 | 股票代码、名称、行业、概念、市场 |

## 3. 标准化推荐格式

建议把每条有效推荐统一成以下结构：

| 字段 | 说明 |
| --- | --- |
| source | 数据来源，如微信个人、微信群、冈底斯、阿尔法派 |
| sender | 发送人/推荐人 |
| message_time | 原始消息时间 |
| raw_content | 原始内容 |
| stock_name | 股票名称 |
| stock_code | 股票代码 |
| market | A股、港股、美股等 |
| action | 买入、卖出、关注、加仓、减仓、观望 |
| confidence | 推荐强度，如高/中/低 |
| horizon | 预期周期，如日内、短线、波段、中线 |
| target_price | 目标价 |
| stop_loss | 止损价 |
| reason | 推荐理由，如业绩、题材、政策、资金、技术形态 |
| sector | 所属行业/题材 |
| extracted_by | 规则、LLM、人工修正 |
| status | 待确认、有效推荐、无效消息、已回测 |

示例：

```json
{
  "source": "微信群",
  "sender": "张三",
  "message_time": "2026-05-21 22:10:00",
  "raw_content": "明天重点看XX股份，低开可以吸，短线看10个点",
  "stock_name": "XX股份",
  "stock_code": "000000",
  "market": "A股",
  "action": "买入",
  "confidence": "中",
  "horizon": "短线",
  "target_price": null,
  "stop_loss": null,
  "reason": "短线机会",
  "sector": null,
  "extracted_by": "LLM",
  "status": "待确认"
}
```

## 4. 数据处理链路

1. 数据采集：定时拉取微信 API 和其他推荐源。
2. 内容清洗：去重、过滤闲聊、表情、转发噪声。
3. 股票识别：从内容中识别股票名称、代码、板块和市场。
4. 推荐意图识别：判断是否为推荐，以及推荐动作、周期、强度。
5. 标准化入库：保存原文和结构化结果，保留可追溯链路。
6. 行情匹配：取推荐后 1日、3日、5日、10日、20日收益表现。
7. 推荐人画像：按人统计胜率、盈亏比、回撤、擅长板块、擅长周期。
8. 看板呈现：展示最新推荐、历史胜率、可跟踪标的和风险提示。

## 5. 推荐人评价指标

| 指标 | 说明 |
| --- | --- |
| 推荐次数 | 有效推荐样本量，样本过少不做结论 |
| 命中率 | 推荐后达到设定收益阈值的比例 |
| 平均收益 | 推荐后固定周期内平均涨跌幅 |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 最大回撤 | 跟随该推荐人的历史最大亏损 |
| 最佳持有期 | 1日、3日、5日、10日、20日哪个周期表现最好 |
| 擅长板块 | 推荐收益较好的行业/题材 |
| 稳定性 | 不同市场环境下表现是否稳定 |

初始建议用多周期指标，不要只看单一胜率。胜率高但盈亏比差的人，实际跟单价值可能不高。

## 7. MVP 建设顺序

### 第一期：数据归纳

交付内容：

1. 接入微信个人消息和微信群 API。
2. 建立标准化推荐表。
3. 自动识别股票、推荐动作、推荐人、推荐时间。
4. 输出每日推荐汇总。

### 第二期：胜率回测

交付内容：

1. 接入行情数据。
2. 计算推荐后多周期收益。
3. 生成推荐人胜率榜。
4. 支持按推荐人、股票、板块筛选。

### 第三期：交易辅助

交付内容：

1. 建立可跟踪推荐池。
2. 识别多人共振、强推荐、高胜率推荐人。
3. 输出风险提示和跟踪状态。
4. 保留人工确认入口，避免直接自动交易。

## 8. 需要老板进一步确认的信息

1. 冈底斯、阿尔法派的数据获取方式：API、文件、短信转发还是网页后台。
2. 行情数据源选择：同花顺、东方财富、Tushare、AkShare、券商接口或其他。
3. 重点市场范围：A股、港股、美股是否都需要。
4. 是否只做推荐分析，还是后续要对接真实交易。
5. 推荐有效性的定义：涨 3% 算命中，还是跑赢指数/板块算命中。
6. 看板优先形式：网页、飞书表格、Excel 报告，还是命令行日报。
