## 3. 关键观察

### 3.1 群消息量大，但噪声也大

群消息数量是个人消息的 3 倍以上，但有效推荐比例不高。群里大量内容是：

1. 研报摘要。
2. 行业日报。
3. 市场闲聊。
4. 重复转发。
5. 活动通知。

模型启发：群消息不能直接进入推荐池，必须先做强分类和去重。

### 3.2 个人消息更接近投研输入，但也不是全是推荐

个人消息里潜在推荐比例更高，但仍有不少活动通知、工具介绍、私人消息。

模型启发：个人消息也不能默认当成推荐，需要先判断消息类型。

### 3.3 重复消息很多

基于消息预览粗看，重复预览有 62 组，涉及 168 行。典型情况：

1. 同一条研报被多个群转发。
2. 同一个发送人在群里连续转发同一主题。
3. 个人消息和群消息同时出现同一内容。

模型启发：必须做内容去重，否则多人共振和推荐人胜率会被虚增。

去重建议：

```text
normalized_content_hash + source + sender + time_bucket
```

其中 `normalized_content_hash` 应先做：

1. 去 emoji。
2. HTML 反转义。
3. 空白归一。
4. 去除常见前缀标签。

### 3.4 多标的消息很多

本次有 87 条消息命中多个公司/标的线索。一条消息可能同时包含多个公司、行业、转债、指数。

模型启发：不能简单取第一只股票做回测。需要判断：

1. 这条消息是单标的推荐，还是行业/日报/列表。
2. 多个标的里哪个是主推。
3. 是否需要拆成多条推荐记录。

建议字段：

```text
is_multi_target
target_role: primary / mentioned / comparison / index
```

### 3.5 “股票相关”不等于“有效推荐”

大量内容虽然包含公司名、股票名、板块名，但本质上只是研究观点或事件解读。

例如：

1. 财报要点。
2. 行业复盘。
3. 策略会邀请。
4. 日报合集。
5. 市场评论。

模型启发：胜率回测只能统计高置信“有效推荐”，不能把所有股票相关内容都纳入。

## 4. 对模型精准度的影响

### 4.1 如果只用关键词，误判会很高

“推荐”“关注”“看好”这些词有用，但不够。比如活动通知里也会出现“欢迎关注”“推荐参会”，研报里也会出现“关注公司”。

第一版规则可以用于粗筛，但不能作为最终分类。

### 4.2 模型需要分两层，而不是一步到位

建议先做消息分类，再做推荐抽取：

```text
原始消息
-> 消息分类
-> 只对有效推荐做结构化抽取
-> 只对高置信推荐做回测
```

这样比直接从所有消息里抽股票更稳定。

### 4.3 推荐置信度必须保留

每条结构化推荐都应该有置信度：

| 置信度 | 说明 | 是否进入回测 |
| --- | --- | --- |
| high | 明确推荐某标的，动作和理由清楚 | 是 |
| medium | 有推荐倾向，但动作/周期不完整 | 可进入观察池，谨慎回测 |
| low | 只是研究观点或提及标的 | 不进入胜率回测 |

### 4.4 推荐人评分要防止样本污染

如果把活动通知、日报合集、多标的列表都算成推荐，推荐人胜率会失真。

推荐人评分应只使用：

```text
category = 有效推荐
confidence = high / medium
target_role = primary
dedup_status = canonical
```

### 4.5 共振信号要先去重

同一条内容被多个群转发，不应该直接算作多人共振。真正的共振应该是：

1. 不同推荐人。
2. 不同来源。
3. 内容不是同一篇原文的重复转发。
4. 推荐时间接近。
5. 推荐标的一致。

否则“共振”会被群转发放大。

## 5. 建议的模型结构

### 第一层：消息分类

输出：

```json
{
  "message_type": "recommendation | research | event | tool | private | noise",
  "confidence": 0.0,
  "reason": "分类原因"
}
```

### 第二层：推荐结构化

只对 `recommendation` 和部分高价值 `research` 运行：

```json
{
  "sender": "推荐人",
  "targets": [
    {
      "stock_name": "股票名称",
      "stock_code": "股票代码",
      "target_role": "primary",
      "action": "关注/买入/加仓/卖出",
      "horizon": "日内/短线/波段/中线",
      "confidence": "high/medium/low",
      "reason": "推荐理由"
    }
  ]
}
```

### 第三层：去重与归并

输出：

```json
{
  "content_hash": "归一化内容 hash",
  "canonical_message_id": "主消息 ID",
  "duplicate_group_id": "重复组 ID",
  "is_duplicate": false
}
```

### 第四层：回测与评分

只对高置信、主标的、去重后的推荐做：

```text
1日 / 3日 / 5日 / 10日 / 20日收益
最大回撤
是否跑赢指数
是否跑赢行业
推荐人胜率
推荐人擅长周期
推荐人擅长板块
```

## 6. 对第一版落地的建议

第一版不要追求“全自动全准确”，而要追求“少误判、可追溯、可解释”。

推荐策略：

```text
规则粗筛
-> LLM 分类与结构化
-> 去重归并
-> 只让高置信推荐进入胜率回测
-> 中低置信进入观察池
-> 所有结论保留原文追溯
```

这样可以优先保证推荐人排行榜的可信度。
