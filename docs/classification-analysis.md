# 消息分类机制与颗粒度分析

> 基于 2026-05-21 实际数据（187 条消息），供与老板讨论分类颗粒度。

## 1. 当前分类体系

| 类别 | 定义 | 后续动作 |
|------|------|---------|
| **recommendation** | 包含明确个股/板块推荐、买入/关注/加仓建议 | → 结构化抽取（ticker/action/strength）→ 观点链归并 |
| **research** | 研报观点、行业分析，但无明确交易建议 | 留存，暂不进入抽取流水线 |
| **event** | 策略会、调研、电话会、路演等活动通知 | 留存参考 |
| **tool** | 软件推荐、工具广告 | 视为噪音 |
| **noise** | 闲聊、私人消息、无关内容 | 丢弃 |

## 2. 分类方式

- **LLM 模式（默认）**：将消息发送给 LLM（当前用 mimo-v2.5），返回类别 + 置信度 + 理由
- **规则降级模式（`--no-llm`）**：关键词正则匹配，如命中"推荐/买入/加仓"→ recommendation，命中"策略会/调研"→ event
- 支持增量分类：已分类的消息不会重复调用 LLM

## 5. 需要讨论的颗粒度问题

### 问题一：research 里是否藏着隐含推荐？

当前 research 有 101 条（54%），只有 recommendation 的 31 条进入抽取流水线。research 中可能存在：
- 研报摘要里提到的重点标的（"我们认为 XX 具有较大弹性"）
- 行业分析中隐含的方向性判断（"光模块板块景气度持续上行"）
- 数据更新类消息（"XX 一季报超预期"）

**选项**：
- A. 维持现状：只抽取明确推荐，research 留存但不进流水线（当前方案，精准但可能漏）
- B. 放宽标准：将 research 中提到具体标的的也纳入抽取（覆盖广但噪音增加）
- C. 新增子类别：将 research 细分为 `research-with-target`（提到具体标的）和 `research-general`（纯宏观/行业）

### 问题二：event 类是否需要结构化？

当前 event 只做标记，不做结构化抽取。但策略会/调研信息本身有价值：
- 哪家券商/哪个行业在开会 → 可能是信号
- 调研的公司 → 可能有近期催化

**选项**：
- A. 维持现状：event 仅标记留存
- B. 做轻量抽取：提取时间、主办方、涉及行业/标的

### 问题三：noise 的边界

28 条 noise 中可能包含简短但有效的信息（如"XX 拉了"、"注意 XX"），当前因为太短且无关键词被归为 noise。

**选项**：
- A. 维持现状：短消息无关键词即为 noise
- B. 降低 noise 门槛：对群消息中的短文本也尝试 LLM 判断（增加 token 消耗）

## 6. 成本参考

- 当前 187 条消息全量 LLM 分类：约 1-2 分钟（10 并发）
- 增量模式下重复运行：0 秒，0 token
- 如果将 research 也纳入抽取：额外 ~101 条 × extract prompt ≈ 增加 3-4 倍 token 消耗
