# 源头雷达策略模型草案

## 1. 目标重定义

源头雷达不应先被定义为热点榜、放量榜或复盘榜，而应定义为：

> 在市场还没有形成一致表达前，发现一个成熟产业链上突然冒出的陌生新词，并把它转成老板可以马上拿去交流、求证和铺垫的情报卡。

老板真正需要的不是“今天哪些词刷屏”，而是：

- 哪个熟悉产业链里出现了一个不熟悉的新表达？
- 这个新表达有没有产业逻辑，不只是券商造词或普通标题？
- 现在是不是足够早，可以拿去问专家、问大佬、提前建立观察池？
- 后续有没有扩散、带股、交易映射，用来验证或证伪？

所以，核心策略应从“低频放量拐点”前移到“源头种子发现”。

## 2. 核心信号结构

一个高价值源头信号至少应包含三段结构：

```text
成熟产业链锚点 + 陌生新词 + 关系证据
```

示例：

| 成熟锚点 | 陌生新词 | 关系证据 |
|----------|----------|----------|
| PCB / 半导体封装 | 半导体化的 PCB | PCB 被重新放进半导体工艺/封装叙事 |
| 淘宝 / 购物 / 电商 | AI 购物 | 千问与淘宝打通，购物入口发生变化 |
| 光模块 / 机柜 | 光入柜内 | 光通信从机间连接进入柜内连接 |
| 电力 / 算力 | 算电协同 | 算力建设和电力系统开始形成新耦合 |

如果只有“陌生新词”而没有成熟锚点，信号容易变成孤立概念；如果只有成熟锚点而没有陌生新词，信号就是旧主题。

## 3. 三层模型

### 3.1 源头发现层

这一层回答：这个东西值不值得第一时间进入老板视野？

判断重点：

- 新词历史冷度：本地历史少见，或首次以当前组合形态出现。
- 成熟锚点强度：能清晰挂到已有产业链、技术路线、产品、政策或应用场景。
- 关系强度：原文能解释“为什么这个新词和成熟锚点有关”。
- 新词形态：具备新概念、新方向、新应用、A 化 B、A 进入 B、A+B 新场景等结构。
- 消息质量：包含产品、技术、订单、客户、政策、工艺、场景等硬信息。
- 来源质量：首发人、首发群是否过去有价值。

这一层不应要求多群扩散。一条高质量首现消息也可以触发。

### 3.2 验证观察层

这一层回答：早期信号有没有开始被别人接力？

判断重点：

- 后续独立发送人数量。
- 后续覆盖群数量。
- 是否跨圈层传播，而不是同一发送人多群搬运。
- 后续消息是否补充了更清晰的产业解释。
- 是否出现公司、产品、订单、客户、政策细节。

放量、接力、T+N 统计属于这一层。它们用于验证源头，不应反过来决定源头是否成立。

### 3.3 交易映射层

这一层回答：这个源头信号能否转成交易观察或动作？

判断重点：

- 是否出现个股映射。
- 个股处于产业链哪个环节。
- 是否进入推荐、策略快报或人工关注池。
- 市场是否已经反应，还是仍有预期差。
- 需要继续跟踪哪些触发器。

这一层输出的是交易观察，不是源头发现本身。

## 4. 状态机

建议把源头信号从一次性榜单升级为状态池。

```text
source_seed -> watching -> spreading -> mapped -> crowded
     |             |           |          |
     v             v           v          v
 dismissed     dismissed   dismissed   review
```

状态定义：

| 状态 | 含义 | 典型触发 |
|------|------|----------|
| source_seed | 源头种子，足够早，值得问 | 成熟锚点 + 陌生新词 + 关系证据 |
| watching | 观察中，证据还不够完整 | 首现质量不错，但缺少扩散或落地信息 |
| spreading | 开始扩散 | 不同人、不同群开始接力 |
| mapped | 出现交易映射 | 出现个股、产业链环节或策略候选 |
| crowded | 已拥挤 | 多群刷屏，可能已经晚了 |
| dismissed | 证伪或降噪 | 泛词、标题党、会议通知、旧主题、无后续 |
| review | 复盘样本 | 用于人工标注和权重更新 |

老板最值得被及时打扰的是 `source_seed` 和 `spreading`：

- `source_seed` 代表足够早。
- `spreading` 代表早期判断开始被验证。

## 5. 排序策略

不要用一个总分直接替代判断。建议分层排序：

### 第一优先级：源头种子质量

- 是否有成熟锚点。
- 是否有陌生新词。
- 是否有清楚的关系证据。
- 新词历史是否冷。
- 首现消息是否短、清晰、可转述。

### 第二优先级：验证强度

- 后续独立发送人。
- 后续群覆盖。
- 是否跨圈层。
- 是否出现更硬的产业证据。

### 第三优先级：交易映射

- 是否带股。
- 是否有产业链位置。
- 是否进入推荐或策略。
- 是否仍有预期差。

放量倍率应作为第二层验证指标，而不是第一层发现指标。否则系统会偏向已经热起来的词，错过真正的首现窗口。

## 6. 建议数据结构

候选不应只存 `term`，而应存结构化源头信息：

```json
{
  "anchor_terms": ["PCB", "半导体封装"],
  "novel_terms": ["半导体化的PCB"],
  "relation_evidence": "PCB 被重新放进半导体工艺/封装叙事",
  "source_status": "source_seed",
  "first_seen": "2026-05-11T09:14:49",
  "first_group": "xxx",
  "first_sender": "xxx",
  "first_message_id": "xxx",
  "history_mentions": 0,
  "anchor_strength": 0.9,
  "novelty_strength": 0.95,
  "relation_strength": 0.85,
  "source_quality": 0.8,
  "followup_senders": 0,
  "followup_groups": 0,
  "mapped_stocks": [],
  "questions": [
    "这是不是行业真实趋势，还是临时造词？",
    "最先受益的是哪个产业链环节？",
    "有没有订单、客户、工艺或产品变化支撑？"
  ]
}
```

## 7. 老板输出形态

输出不应只是榜单，而应是“可问卡片”。

```text
【源头种子】半导体化的 PCB

成熟锚点：PCB / 半导体封装
陌生新词：半导体化的 PCB
首现：2026-05-11 09:14，某群 / 某发送人

为什么值得问：
它把 PCB 从传统电子材料叙事，嫁接到半导体工艺/封装叙事。

建议问谁：
PCB、封装、材料、设备方向专家。

建议问什么：
1. 这是不是行业真实趋势，还是券商造词？
2. 哪些环节最先受益？
3. 有没有订单、客户、工艺或产品变化支撑？

观察触发器：
- 是否出现带股。
- 是否被其他群或其他发送人接力。
- 是否出现订单、客户、产能、技术路线等硬证据。
```

这种输出可以直接帮助老板拿去交流，而不是只告诉他“倍率很高”。

## 8. 对现有实现的调整方向

### 8.1 抽取层

从抽 `terms` 升级为抽：

- `anchor_terms`
- `novel_terms`
- `relation_evidence`
- `source_type`
- `why_now`
- `suggested_questions`

LLM 的主要职责不是判断热度，而是识别“熟悉锚点 + 陌生表达 + 关系”。

### 8.2 扫描层

扫描层继续保持纯本地，但指标重心调整：

- 历史冷度：用于判断新词是否陌生。
- 锚点历史：用于判断成熟产业链是否成立。
- 首现时间：用于判断是否足够早。
- 后续接力：用于状态升级。
- 带股和推荐：用于交易映射。

### 8.3 榜单层

把一个榜拆成三块：

1. 今日源头种子：最早、最值得问。
2. 正在扩散：已经有人接力，值得重点盯。
3. 已带股/已拥挤：进入交易映射或提醒可能晚了。

## 9. 验收指标

需要用人工复盘来评估，不只看命中案例。

建议指标：

- 源头有效率：TOP 10 里人工认为值得问的比例。
- 提前量：首次提示距离多群刷屏相差多久。
- 可问率：输出是否能形成明确专家问题。
- 泛词误报率：行动方案、会议、策略、行业等泛词占比。
- 重复事件占比：同一事件在榜单里占多个位置的比例。
- 后续验证率：进入 `spreading` / `mapped` 的比例。
- 过热率：提示时是否已经刷屏，是否已经失去提前意义。

## 10. 一句话原则

源头雷达的核心不是找最热的词，而是找：

> 一个熟悉产业链上突然冒出的陌生表达，并把它转成老板可以马上拿去问人的情报卡。

## 11. 4-5 月数据观察

### 11.1 数据覆盖

基于本地 2026-04-01 至 2026-05-31 数据做了一轮只读统计：

| 口径 | 数量 |
|------|-----:|
| 日期 | 61 天 |
| raw 去重消息 | 146,607 |
| 个人群 raw 去重消息 | 103,868 |
| classified 消息 | 97,624 |
| research 分类 | 35,599 |
| event 分类 | 17,529 |
| recommendation 分类 | 19,280 |
| source_extract 结果 | 2,462 |
| source_extract 候选 | 784 |

关键限制：`source_extract` 目前只覆盖 2026-05-11、2026-05-30、2026-05-31 三天。4 月和 5 月大部分日期虽然有 raw / classified / research，但没有源头抽取产物。

结论：不能只用已有 `source_extract` 来验证“首现”。否则很多词会被误判成“第一次被系统看到”，而不是真正在本地语料里第一次出现。

进一步把已有 `source_extract` 的 1,413 个唯一候选词，回到 4-5 月个人群 raw 里做原文子串首现匹配：

| 首现相对 source_extract | 词数 |
|-------------------------|----:|
| 同一天出现 | 224 |
| 提前 1-3 天出现 | 45 |
| 提前 4-7 天出现 | 19 |
| 提前 8-14 天出现 | 23 |
| 提前 14 天以上出现 | 309 |
| raw 中无法按原词子串匹配 | 773 |

在能用原文子串匹配验证的 640 个词里，396 个词早于抽取日出现，占比约 62%。这说明当前 `source_extract` 的日期覆盖不足会严重污染“首现”判断。`raw 中无法匹配` 的部分也有意义：说明 LLM 已经在做归纳/改写，后续状态池不能只靠精确子串，还需要保存 `first_message_id`、`relation_evidence` 和归一化别名。

### 11.2 现有放量榜的偏差

用现有 `sn source scan` 跑 2026-05-30 和 2026-05-31 后，能看到几个典型偏差：

- 2026-05-30 TOP 出现 `打破国外垄断`。
- 2026-05-31 TOP 出现 `未来产业`、`十五五规划`。
- 这些词因为后续扩散或带股，会被 `低频拐点 + T+N` 机制顶上来。

这类词不一定没价值，但它们更像政策/新闻/事件催化，不是老板要拿去问人的“成熟产业链上冒出的陌生新表达”。

结论：放量榜适合做验证和复盘，不适合作为源头发现主榜。

### 11.3 从 research 原文直接扫出的启发

对 4-5 月 classified=research 的个人群消息做规则探索：

- 宽松触发词规则扫出约 9,557 条“像源头”的消息，但样本里大量是周报、长观点、标题集合、普通行业观点，过召回明显。
- 只看强触发词（新概念/新方向/新应用/从0到1/进入新阶段等）约 173 条。
- 再叠加短消息、非会议/周报、有产业锚点后，只剩约 21 条。

结论：老板级实时提醒应该走高精度“源头种子”通道，宁可少，不要把长研报、周观点和普通政策标题推上来。召回可以留给观察池和日终复盘。

把 research 和 event 一起看，压缩效果更明显：

| 阶段 | 数量 |
|------|----:|
| 个人群 research/event 基础样本 | 43,869 |
| 宽松触发（A 化 B、A+B、映射、催化等） | 12,186 |
| 强触发（新概念/新方向/新应用/从0到1等） | 199 |
| 强触发 + 非会议/周报 | 163 |
| 强触发 + 有产业锚点 | 172 |
| 强触发 + 短消息 | 52 |
| 强触发 + 短消息 + 非会议/周报 + 有锚点 | 24 |

这组数说明两个问题：

1. 宽松规则不能直接推送，12,186 条太多，且噪音结构明显。
2. 过硬的短消息过滤虽然能提精度，但会漏掉“标题很强、正文很长”的研究消息。下一版更合理的做法是抽取 `title_or_lead` 作为源头种子判断对象，把长正文作为关系证据，而不是简单按全文长度过滤。

### 11.4 真实词轨迹说明“首现”和“扩散”必须拆开

抽查若干词在 4-5 月个人群语料中的轨迹：

| 词 | 本地首次出现 | 4-5 月总提及 | 启发 |
|----|--------------|-------------:|------|
| 半导体化的 PCB | 2026-05-11 | 59 | 符合“源头种子 + 快速扩散”，是理想样本 |
| AI 购物 | 2026-04-09 | 16 | 5/11 放量前，4 月已有首现；只看 5/11 会晚 |
| 法拉第旋光片 | 2026-04-03 | 27 | 早期长期低频，后续才被放大 |
| 光入柜内 | 2026-04-01 | 35 | 4 月已有首现，5 月放量不是源头时刻 |
| Token 经济学 | 2026-04-02 | 34 | 低频长尾发酵，不一定当天放量 |
| 物理 AI | 2026-04-02 | 319 | 后续明显扩散，但首现和刷屏相隔较远 |
| PPO | 2026-04-01 | 138 | 首现可能是长消息，后续多日扩散 |
| 电碳协同 | 2026-05-12 | 2 | 几乎没扩散，但可能正是老板要拿去问的早期种子 |
| 未来产业 | 2026-04-09 | 79 | 放量/政策价值有，但新词特征弱 |
| 十五五规划 | 2026-04-01 | 61 | 政策催化，不应和源头新词混排 |

结论：有些最值得早问的词，在首现当天可能只有一两条；有些后续很热的词，源头时刻在很早之前。系统必须同时记录“首现种子”和“后续扩散”，不能用后续扩散倒推源头。

### 11.5 新旧判断必须使用事件时间视角

“新不新”不能用复盘当天的全局视角判断，而必须使用 `as_of_time`：

```text
在 T 时刻，只能使用 T 之前的本地历史判断冷度；
T 之后出现的扩散、带股、复述，只能用于验证，不能反过来改写 T 时刻的新旧结论。
```

例如 `金刚石涂层 PCB 钻针` 站在 2026-05-11 看已经不是全新主题，因为 `PCB 钻针` 和 `金刚石涂层` 在 4 月已有多次出现；但如果站在它最早被清楚表达、且尚未扩散的当天，它就可能是有效的 `source_seed`。同理，`半导体化的 PCB` 在 2026-05-11 是源头种子，2026-05-13 多群复发时已经进入 `spreading_watch`，不能再按源头首现处理。

因此系统需要支持“事件时间回放”：

- 实时推送时，用当前时刻的历史状态判断。
- 复盘评估时，用候选出现当时的历史快照判断。
- 模型训练/规则调参时，禁止使用候选之后的数据作为源头发现特征，只能作为标签或验证结果。

## 12. 基于数据的策略修正

### 12.1 两条主线

应该拆成两条主线：

1. `source_seed`：源头种子发现，追求早和可问。
2. `spreading_watch`：扩散观察，追求验证和交易映射。

`source_seed` 可以只出现一条消息，只要满足：

- 有成熟产业链锚点。
- 有陌生新表达。
- 原文能说明二者关系。
- 标题或首句足够清楚、可转述，长正文只作为证据补充。
- 能抽出清晰的可问问题。

`spreading_watch` 才使用：

- 当日放量。
- 后续独立发送人。
- 后续覆盖群。
- T+N 是否带股。

### 12.2 三类信息不要混排

数据里至少有三类信号，应该分栏而不是混在一个 TOP 榜里：

| 类型 | 例子 | 产品动作 |
|------|------|----------|
| 源头种子 | 半导体化的 PCB、电碳协同、Token 经济学 | 生成可问卡片 |
| 扩散验证 | 某词多群接力、多人转述、开始带股 | 升级状态、提醒复盘 |
| 政策/事件催化 | 十五五规划、未来产业、行动方案 | 放到事件催化栏，不占源头种子榜 |

这样可以避免“政策大词因为放量高而挤掉真正陌生新词”。

### 12.3 连续状态池是必要条件

由于 4 月和 5 月很多词的真实首现早于已有 `source_extract` 日期，后续必须补一个连续状态池：

```text
raw/classified research
  -> source_seed harvest
  -> term_state.json
  -> 每日增量更新 first_seen / first_message_id / status
  -> 后续扩散和带股只做状态升级
```

如果没有连续状态池，系统会反复把“今天第一次被抽到”误认为“本地首次出现”。

### 12.4 抽取模型要从 term 改成结构

现有 `terms` 会抽出一些不适合作为源头词的表达，例如泛政策词、泛动作词、公司名或新闻标题片段。

下一版抽取应要求模型输出：

- `anchor_terms`：成熟产业链锚点。
- `novel_terms`：陌生新表达。
- `title_or_lead`：最能代表源头种子的标题或首句。
- `relation_evidence`：锚点和新表达之间的关系证据。
- `relation_type`：例如 `A化B`、`A进入B`、`A+B新场景`、`瓶颈转移`、`政策催化`、`产品落地`。
- `askability_score`：老板拿去问人的价值。
- `suggested_questions`：三条可问问题。
- `noise_reason`：如果只是周报、会议、政策大词、普通标题，明确降噪原因。

抽取判断应优先围绕 `title_or_lead`，而不是全文。长消息如果只是周报、观点合集或标题集合，应降噪；但长消息里如果首句就是清晰的“成熟锚点 + 陌生新词”，正文可以保留为解释材料。

### 12.5 需要新增负向规则

从数据看，以下词形容易误上榜：

- 泛政策词：未来产业、十五五规划、行动方案。
- 泛动作词：打破国外垄断、战略合作、加速窗口。
- 单纯公司/个股名。
- 会议、周报、活动、电话会标题。
- 长篇研报中的目录式标题集合。

这些不应直接进入源头种子榜；可以进入事件催化或观察池。

### 12.6 新的验收方式

后续验证不能只看“有没有扩散/带股”，还要看是否满足老板动作。

建议人工标注每条候选：

```text
0 = 噪音，不值得看
1 = 有信息，但只是普通催化/旧主题
2 = 值得观察，但暂时不可问
3 = 可问，老板能拿去找人交流
4 = 高价值源头，且后续被扩散或带股验证
```

核心指标：

- `可问率`：TOP 源头种子里 3 分以上占比。
- `提前量`：提示时间距离多群刷屏/带股相隔多久。
- `误占位率`：政策大词、泛词、公司名占 TOP 的比例。
- `状态升级率`：source_seed 后续进入 spreading/mapped 的比例。
- `漏报复盘`：人工认为高价值但系统没有提示的样本。

## 13. V0 可执行规则

### 13.1 输入范围

V0 不需要先重跑全量 LLM。可以先从本地数据里做纯本地候选池：

- 主输入：classified 为 `research` 的个人群消息。
- 辅助输入：classified 为 `event` 且带强产业/政策/产品触发的个人群消息。
- 不直接使用 recommendation 做源头种子，但可用于后续交易映射。

### 13.2 源头种子准入

一条候选进入 `source_seed`，至少要满足：

```text
有成熟产业链锚点
+ 有陌生新表达
+ 有关系证据
+ title_or_lead 可转述
+ 不是会议/周报/政策泛词/公司名
```

推荐硬门槛：

- `anchor_terms` 非空。
- `novel_terms` 非空，且不是泛词。
- `relation_evidence` 能说明新词为什么挂在锚点上。
- `askability_score >= 0.7`。
- `title_or_lead` 不超过 120 字；全文可以更长，但不能只是多标题合集。

### 13.3 硬拒绝规则

以下内容不进 `source_seed`：

- 会议、电话会、路演、活动、日程、报名。
- 周报、日报、月报、复盘、观点合集。
- 单纯公司深度、个股推荐、业绩点评。
- 泛政策词或宏观大词：例如 `未来产业`、`十五五规划`、`行动方案`。
- 泛动作词：例如 `打破国外垄断`、`战略合作`、`加速窗口`。
- 只有成熟锚点、没有陌生新词。
- 只有陌生词、但无法说明和成熟链条的关系。

这些内容可以进入 `event_catalyst` 或 `watching`，但不占老板实时源头种子名额。

### 13.4 排序口径

`source_seed` 排序按以下顺序：

1. `askability_score`：老板能不能立刻拿去问人。
2. `relation_strength`：成熟锚点和陌生新词的关系是否清楚。
3. `novelty_strength`：陌生新词在历史上是否冷。
4. `source_quality`：首发人/群是否可信，消息是否清晰。
5. `first_seen`：越早越优先。

不要把 `surge_ratio` 放进源头种子主排序。放量只用于 `spreading_watch` 状态升级。

### 13.5 状态升级规则

```text
source_seed
  -> spreading_watch   后续出现 >=2 个独立发送人接力，或 >=3 个群扩散
  -> mapped            后续出现明确个股/产业链环节
  -> crowded           多群刷屏，提示可能已经晚
  -> dismissed         3-5 天无接力，或人工判定为泛词/旧主题
```

注意：`dismissed` 不代表首发判断失败。有些词像 `电碳协同` 可能没有扩散，但仍可能是值得老板问人的早期线索；它应该进入复盘样本，判断“可问但未扩散”和“噪音”之间的差异。

### 13.6 输出名额

建议老板实时输出控制在很少量：

- `source_seed`：每半天 3-5 条。
- `spreading_watch`：只推状态升级，不重复推旧词。
- `event_catalyst`：单独摘要，不和源头种子混排。

这个名额设计来自数据观察：宽松规则会产生上万条候选，而高精度规则只有几十条。老板需要的是少量可行动情报，不是信息流再压缩一遍。

## 14. 落地架构

### 14.1 总体链路

```text
raw / classified
  -> candidate_harvest      抽取候选标题、首句、锚点、新表达
  -> state_update           按 as_of_time 更新历史状态池
  -> source_seed_rank       输出今日源头种子
  -> spread_verify          观察 T+3 / T+5 扩散、接力、带股
  -> review_dataset         人工标注，用于规则和模型迭代
```

这条链路和盘中策略快报分开。盘中策略快报回答“现在交易什么”，源头雷达回答“现在该提前问什么”。

### 14.2 运行节奏

建议分三种任务：

| 任务 | 频率 | 是否实时 | 目标 |
|------|------|----------|------|
| 增量源头扫描 | 20-30 分钟一次 | 是 | 发现 `source_seed`，少量推送 |
| 每日状态复盘 | 每日收盘后 | 否 | 更新扩散、带股、拥挤、证伪 |
| 周度人工审阅 | 每周一次 | 否 | 标注好坏样本，修正规则和模型 |

实时任务只做轻量判断，避免为了等 LLM 或完整交易映射而错过首发窗口。更重的解释、归因、训练样本沉淀放到每日/周度任务。

### 14.3 实时模式与状态回看模式

实时当天不能使用 T+3/T+5 指标自证，因为未来数据还没有发生。系统应拆成两种模式：

```text
实时模式：
  只看 as_of_time 之前的历史
  输出 source_seed
  标记待验证项

状态回看模式：
  回看过去 1-5 天已经进入状态池的 source_seed
  使用现在已经发生的数据更新 spreading / mapped / crowded / dismissed
```

因此每日输出不是一个单日热词榜，而是三个状态栏：

| 栏目 | 数据来源 | 使用数据 | 输出目的 |
|------|----------|----------|----------|
| 今日源头种子 | 今天新出现的候选 | 只用 `as_of_time` 之前历史 | 早期可问，不要求自证 |
| 正在扩散 | 过去 1-3 天的 `source_seed` | 用已经发生的 T+1/T+3 接力数据 | 提醒早期判断开始被验证 |
| 已映射/已拥挤 | 过去 1-5 天的 `source_seed` | 用已经发生的带股、刷屏、同质转发 | 进入交易观察，或提示可能已经晚 |

例如：

```text
T 日：半导体化的 PCB -> source_seed，只能说“值得问，待验证”
T+3：多群复发、多人接力 -> spreading_watch
T+5：开始带股或同质刷屏 -> mapped / crowded
```

如果当天任务发现的是 3 天前或 5 天前已经出现过的 signal，就不应把它当作今日源头首现，而应进入状态回看：该自证就升级为 `spreading_watch` 或 `mapped`，已拥挤就标记为 `crowded`。

### 14.4 状态池

需要维护一个连续状态池，不能只依赖当天抽取结果。

核心字段：

```json
{
  "signal_id": "anchor+novel 的归一化哈希",
  "anchor_terms": ["PCB", "半导体封装"],
  "novel_terms": ["半导体化的PCB"],
  "aliases": ["PCB半导体化", "半导体化PCB"],
  "first_seen": "2026-05-11T09:14:49",
  "first_message_id": "xxx",
  "first_sender": "xxx",
  "first_group": "xxx",
  "as_of_time": "2026-05-11T09:14:49",
  "status": "source_seed",
  "lookback_mentions": 0,
  "lookback_days": 30,
  "followup_senders": 0,
  "followup_groups": 0,
  "mapped_stocks": [],
  "last_pushed_at": null,
  "review_label": null
}
```

状态池的关键不是“保存词”，而是保存“这个词第一次是在哪条消息、什么上下文里被看见”。否则复盘时无法判断它当时到底是不是新。

## 15. 指标设计

### 15.1 发现指标

发现指标只使用 `as_of_time` 之前的数据。

| 指标 | 含义 | 计算口径 |
|------|------|----------|
| `lookback_30d_mentions` | 近 30 天历史提及 | 候选出现前 30 天，精确词 + 别名匹配 |
| `lookback_60d_mentions` | 近 60 天历史提及 | 辅助判断长期冷度 |
| `combo_mentions` | 组合历史提及 | 同一“锚点 + 新表达”组合在历史里出现次数 |
| `first_seen_gap_days` | 距首次出现天数 | `as_of_time - first_seen` |
| `anchor_strength` | 成熟锚点强度 | 锚点在历史中稳定出现，且属于产业链/技术/产品 |
| `novelty_strength` | 新颖度 | 历史越少、组合越新，分数越高 |
| `relation_strength` | 关系强度 | 原文是否解释锚点和新表达为什么有关 |
| `askability_score` | 可问性 | 能否形成专家问题和产业链追问 |

推荐 V0 新颖度规则：

```text
lookback_30d_mentions = 0       -> novelty_strength 高
lookback_30d_mentions <= 2      -> novelty_strength 中高
lookback_30d_mentions <= 5      -> novelty_strength 中
lookback_30d_mentions > 5       -> 降级为 watching / spreading_watch
combo_mentions = 0              -> 组合新颖度加分
```

这个规则要区分“单词新”和“组合新”。例如 `半导体化` 或 `PCB` 单独不新，但 `半导体化的 PCB` 在当时作为组合首次出现，仍然可以是高价值源头。

#### 单词新与组合新

LLM 不负责判断“新不新”。它只负责把文本拆成可查结构；新颖度由本地历史索引计算。

以 `正在半导体化的 PCB` 为例，系统应拆出：

```json
{
  "title_or_lead": "正在半导体化的PCB",
  "anchor_span": "PCB",
  "anchor_normalized": "PCB",
  "novel_span": "半导体化的PCB",
  "modifier_span": "半导体化",
  "relation_type": "A化B",
  "signal_id": "PCB::A化B::半导体化"
}
```

然后分别查历史：

| 口径 | 示例 | 用途 |
|------|------|------|
| 锚点历史 | `PCB` | 判断是不是成熟产业链 |
| 修饰词历史 | `半导体化` | 判断单词本身是否少见 |
| 原词组历史 | `半导体化的 PCB` | 判断精确表达是否首次出现 |
| 组合关系历史 | `PCB::A化B::半导体化` | 判断“老锚点 + 新修饰/新关系”是否首次出现 |
| 同义组合历史 | `PCB 半导体化`、`PCB 向半导体化演进` | 判断是否只是同一表达的变体 |

最终结论可能是：

```text
PCB 很成熟
半导体化不是完全新
但 PCB::A化B::半导体化 在 as_of_time 前没有出现
=> 单词不新，组合新
```

这也是后续实现里的关键约束：`novelty_strength` 不能只看 `novel_terms` 的词频，还要看 `signal_id` 和同义组合的历史冷度。

### 15.2 验证指标

验证指标只使用 `as_of_time` 之后的数据。

| 指标 | 含义 | 计算口径 |
|------|------|----------|
| `t1_mentions` | T+1 天提及 | 后续 1 天内命中次数 |
| `t3_unique_senders` | T+3 独立接力人 | 排除同一人多群搬运 |
| `t3_unique_groups` | T+3 群覆盖 | 后续 3 天覆盖群数 |
| `cross_circle_score` | 跨圈层程度 | 不同券商/不同群类型/不同发送人 |
| `mapped_stock_count` | 落地个股数 | 后续推荐/观点中出现的个股数量 |
| `crowding_score` | 拥挤度 | 多群刷屏、同质转发、带股过多 |

验证指标不能用于判断“当时新不新”，只能用于状态升级和复盘标签。

### 15.3 输出质量指标

这些指标用于衡量给老板的结果是否有用。

| 指标 | 目标 |
|------|------|
| `top5_askable_rate` | TOP 5 中人工标 3 分以上的比例 |
| `early_window_hours` | 首次推送距离明显扩散/带股提前多少小时 |
| `noise_occupation_rate` | TOP 中泛词、政策词、会议、公司名占比 |
| `duplicate_signal_rate` | 同一主题重复占多个名额的比例 |
| `missed_gold_count` | 人工 gold sample 中系统漏掉的数量 |
| `source_to_spreading_rate` | source_seed 后续进入 spreading 的比例 |
| `source_to_mapped_rate` | source_seed 后续出现交易映射的比例 |

第一阶段最重要的不是 `source_to_mapped_rate`，而是 `top5_askable_rate` 和 `early_window_hours`。否则系统会被训练成“等交易机会明确后再报”，又回到晚报。

## 16. 模型设计

### 16.1 V0：规则 + LLM 结构抽取

V0 不需要复杂机器学习，先做高精度闭环。

规则负责：

- 过滤明显噪音。
- 计算历史冷度、组合冷度、扩散、带股。
- 维护状态池。
- 控制推送名额。

LLM 负责：

- 从标题/首句中抽 `anchor_terms` 和 `novel_terms`。
- 输出原文里的 `anchor_span`、`novel_span`、`modifier_span`，不能只输出自由总结。
- 判断关系类型。
- 生成 `relation_evidence`。
- 生成老板可问的问题。
- 给出噪音原因。

LLM 输出必须能回指原文。如果不能在 `title_or_lead` 或正文中定位到明确 span，就降级为 `watching` 或丢弃。新颖度判断不问 LLM，而是用这些 span 生成 `signal_id` 后查本地历史。

V0 的目标是让老板看到 3-5 条“能问”的信号，而不是追求召回所有概念。

### 16.2 V1：学习排序模型

当人工标注累计到 200-500 条后，再训练或拟合一个轻量排序模型。

输入特征：

- 发现特征：历史冷度、组合冷度、锚点强度、关系强度、消息长度、标题位置。
- 来源特征：发送人历史命中率、群历史命中率、是否跨圈层首发。
- 文本特征：A 化 B、A+B、新应用、新路线、瓶颈转移、产品/工艺/客户/订单词。
- 验证标签：T+3 接力、T+5 带股、人工评分。

标签设计：

```text
0 噪音
1 普通信息
2 可观察
3 可问
4 高价值源头且后续验证
```

训练时要严格按事件时间切分，不能让模型看到候选之后的数据作为输入特征。后续扩散和带股只能作为标签。

### 16.3 V2：老板样本校准

真正贴近老板，需要建立 gold sample。

每周整理：

- 老板认为值钱的源头样本。
- 老板觉得不值钱但系统推了的样本。
- 后来被市场验证但系统漏掉的样本。

每条样本至少标注：

```text
为什么值钱：
- 新表达是什么
- 成熟锚点是什么
- 当时早不早
- 能问谁
- 后来有没有扩散
- 有没有落到个股
```

这个样本集比模型本身更重要。没有老板样本，系统只能学到“市场热不热”；有老板样本，系统才可能学到“老板觉得什么值得提前问”。

## 17. 分阶段交付

### 阶段一：可审阅原型

目标：用 4-5 月数据跑出可复盘样本，不急着恢复定时推送。

交付：

- 新的结构化候选表。
- `source_seed / spreading_watch / mapped / crowded` 状态输出。
- 5/11-5/13 案例复盘：`半导体化的 PCB`、`CIPB-PCB`、`金刚石涂层 PCB 钻针`。
- TOP 20 人工审阅清单。

验收：

- 是否能在 5/11 把 `半导体化的 PCB` 放进源头种子。
- 是否能在 5/13 把它识别为扩散，而不是再次当作首现。
- 是否能把 `CIPB-PCB` 识别为高新颖度但低扩散的 source_seed。
- 是否能把已存在较久的 `PCB 钻针` 降级为旧主题延续或交易映射。

### 阶段二：低频试运行

目标：每天 1-2 次人工审阅，不直接打扰老板。

交付：

- 每日源头种子摘要。
- 每日扩散升级摘要。
- 人工标注入口或本地标注文件。
- 误报/漏报复盘。

验收：

- TOP 5 可问率达到 60% 以上。
- 泛词/会议/政策误占位明显下降。
- 每天输出不超过 5 条 source_seed。

### 阶段三：恢复定时推送

目标：只把高置信、低噪音、可问的卡片推给老板。

推送规则：

- 只推 `source_seed` 中 `askability_score >= 0.8` 且 `novelty_strength >= 0.7` 的候选。
- 同一 `signal_id` 只推一次。
- 后续状态升级只推关键变化，例如从 `source_seed` 到 `spreading_watch` 或 `mapped`。
- `crowded` 只做提醒，不当作新机会。

验收：

- 老板主观认为“有用/可问”的比例稳定。
- 每周能沉淀 3-5 个可复盘案例。
- 漏报样本能反向进入规则或模型迭代。
